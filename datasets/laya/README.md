# Laya trainable format (JSONL)

Converted from the raw data in `../CFSC-ABSA`, `../FinFE`, and `../FinNSP` by `to_laya_format.py`.
`validate_laya_format.py` checks the result against Laya's official source rules with **0 errors**.

## 1. Laya training data schema

Aligned with the official `docs/finetune.md` and `laya/train.py`:

```json
{"state": "text or JSON state",
 "questions": {"qid": {"type": "choice|score|noul", "instructions": "...", "criteria": {...}}},
 "expected": {"qid": answer}}
```

- `state`: the text to judge (a dict also works and gets serialized)
- `questions`: keys are question ids, values are question definitions; **a given qid's definition must be consistent across all lines**
- `expected`: one gold answer per question (`gold` can instead hold a teacher probability distribution)
  - `choice` → the option string (must be a key of `criteria`)
  - `noul` → `true` / `false`
  - `score` → the score level
- **A line without `expected` is inference input**, usable directly with `predict` / `laya-evals`

## 3. Question design for the three tasks

### 1. CFSC-ABSA → `sentiment_absa` (choice, 1 of 3)

```json
{"state": "<aspect term>: 湖南\n<sentence>: ...【湖南】、江西增速分别提高1.4和0.7个百分点...",
 "questions": {"sentiment_absa": {"type": "choice",
   "instructions": "<what sentiment does this sentence express toward the given aspect term?>",
   "criteria": {"positive": "...", "neutral": "...", "negative": "..."}}},
 "expected": {"sentiment_absa": "positive"}}
```

> The JSON samples in this section are **verbatim excerpts of the generated Chinese data**, so the values stay in Chinese. The surrounding text and the `instructions`/`criteria` semantics are described in English below.

- The original data has one sample per aspect term; that granularity is preserved here (41,496 rows)
- `state` marks the aspect term with `【】`, so the "given aspect term" condition of ABSA is fed explicitly to a unidirectional encoder. If the original `from`/`to` offsets do not match the actual substring, `find()` is used as a fallback
- Class distribution: train positive 20,385 / neutral 4,228 / negative 8,571; test positive 5,134 / neutral 1,032 / negative 2,146

### 2. FinFE → `sentiment_social` (choice, 1 of 3)

```json
{"state": "<Chinese financial social-media post>",
 "questions": {"sentiment_social": {"type": "choice", "instructions": "...",
   "criteria": {"negative": "...", "neutral": "...", "positive": "..."}}},
 "expected": {"sentiment_social": "positive"}}
```

The original labels `0/1/2` map to `negative/neutral/positive` (**not** the usual 0/1/2 order; the conversion follows the official mapping).
train negative 4,690 / neutral 4,143 / positive 7,324; eval negative 574 / neutral 560 / positive 886.

### 3. FinNSP → `neg_has` (noul) + `neg_subject` (choice)

```json
{"state": "<candidate entities: A; B; C>\n<text>: ...",
 "questions": {"neg_has": {"type": "noul", "instructions": "<does the text contain negative news about the given candidate entity?>..."},
               "neg_subject": {"type": "choice", "instructions": "<which entity is the subject of the negative news?>",
                               "criteria": {"<entity A>": "...", "<entity B>": "...", "<none of the above>": "..."}}},
 "expected": {"neg_has": true, "neg_subject": "<entity A>"}}
```

- The original row structure is `[id, redundant field, body, candidate entities, has-negative, negative subject]`
- `neg_has`: noul, asked on all 4,000 rows
- `neg_subject`: **asked only when `neg_has=true`** (2,221 rows), so negative examples need not guess a subject
- The subject question offers **20 fixed high-frequency entities plus a single `none-of-the-above` option**, because Laya requires a qid's `questions` definition to be consistent across all lines (`train.py` only warns on conflict when exporting `questions.json` and keeps the first definition; dynamic candidates would make the option space unrecoverable at inference time)
- The entity vocabulary is counted from the training set only, and near-duplicates are merged after normalization (stripping parenthetical notes and whitespace), e.g. one short alias and the two full company names
- Trade-off and residual issue: **102/259 (39%)** of positive subjects in the validation set fall outside the vocabulary and are answered as `none-of-the-above`. Raising `NSP_VOCAB_SIZE` covers more, but Laya's own documentation notes that accuracy drops noticeably past ~20 options; a more robust approach is to split by entity domain into several sub-tasks, each posing its own choice question.

## 4. The `meta` field

Every line carries `meta`. **Laya does not read it during training**; it is kept for traceability and retrospective scoring:

- `meta.source`: `CFSC-ABSA` / `FinFE` / `FinNSP`
- `meta.split`: `train` / `test` / `eval`
- ABSA: `term`, `category` (Corporate/Stock/Market/Economy), and the original `from`/`to`
- FinNSP: `id`, `candidates` (that sample's original candidate list), `subjects` (gold subjects)

## 5. Training directly on it

```bash
pip install laya
laya-train --data all_train.jsonl --base multilingual --out ./laya-fin-sent
# or dry-run first to check the read/skip counts and the optimizer step budget, without loading weights
laya-train --data all_train.jsonl --base multilingual --dry-run
```

Note: `--base` must be a `multilingual` or `chinese` backbone — **do not use the English `laya`**. Chinese text degrades to near-random on the English checkpoint. To validate a single file, use
`laya-evals run finfe_eval.jsonl --model multilingual`.

## 6. Regenerating and validating

```bash
python to_laya_format.py        # reconvert, output to laya/
python validate_laya_format.py  # validate; exit code 0 means everything is legal
```

The validation covers: valid question types, non-empty `instructions`, choice labels being unique scalars, noul answers being booleans, choice answers falling within `criteria`, a qid's schema being consistent across lines, and every `expected` key being defined.
